How the input streams are drawn — a visual walkthrough of model_v07.md §7.4

Every unsimulated input in the v07 model — cortex onto the striatal microcircuit, the missing GABA from striatum outside the cube, cortex onto thal/GPe/STN — is a stream: a precomputed matrix of spike counts. This page walks through how one is drawn, on toy examples small enough to draw every neuron, and then proves on each case that the real generator (spike_input_cortex.py) produces exactly the statistics the toy explains. Toy numbers are deliberately exaggerated (shared fraction 0.2 instead of 0.014) so overlap is visible; every section carries the real numbers alongside.

1 · What a stream is, and what it must reproduce

One stream serves one (pre, post) pair. Row i is receiver i, column t is one dt = 0.1 ms bin, and the entry is a count: how many of the pair's presynaptic neurons spiked into receiver i in that bin. No spike trains, no individual synapses — a single mean weight turns counts into current later.

The stream stands in for N neurons firing at probability p(t) = rate(t)·dt/1000 per bin, whose afferent pools overlap between two receivers by a fraction f, and which may themselves be pairwise correlated at ρ. Three statistics then follow with no freedom, and the generator is checked against them at build time (stream_target_statistics, check_stream_statistics): 

mean = N · p(t)
Fano = (1 − p) · ((1 − ρ) + N·ρ)          → 1 − p       when ρ = 0
corr = (f·(1 − ρ) + N·ρ) / ((1 − ρ) + N·ρ) → f           when ρ = 0

The one principle behind all three constructions: realise the presynaptic pool explicitly and let overlap produce the correlations — never compute a correlation and impose it. (The pre-2026-08-07 code imposed it through a Gaussian copula and delivered corr 0.00009 where 0.014 was intended, Fano 1922 where 1 was.)

3 · Case 1a — cortex → striatum: one axon pool per region

Think of one cortical region, say dlPFC. Its axons crossing the striatal tissue form one pool of M axons, and every receiver — dSPN, iSPN or FS alike — owns a random subset of it: N_i = round(proportion(region) · N_cortical_inputs[type]) axons. The shared input between two receivers is simply the axons in both subsets.

Why M = N/f realises the shared fraction. Two SPNs each picking N axons uniformly from M share N²/M axons on average — a fraction N/M of their pools. Kincaid's measurement says that fraction is 0.014, so the pool size is defined by it: M = round(N_eff(dSPN)/0.014). For dlPFC: 3850/0.014 = 275 000 axons. f is never imposed anywhere — M is chosen so overlap produces it.

Why once per region, not per stream. All three receiver types sample the same physical axons, so the three streams are drawn together against one pool. Drawn separately, a dSPN and an iSPN in the same tissue would share nothing. The cross-type shared fractions then follow from M instead of being free parameters (table below).

Per bin, the draw needs no membership matrix (simulate_cortical_axon_pool_streams_to_memmap): 

k(t)   ~ Binomial(M, p(t))                        # how many pool axons fire — ONCE, shared
c_i(t) ~ Hypergeometric(N_i, M − N_i, k(t))       # how many of them receiver i owns

The hypergeometric is the marbles question — of the k firing axons, how many land in my N_i? — and because the subsets are uniform random, that distribution is exact without knowing which axons are whose. All coupling between receivers comes from the shared k(t): a bin where the pool fires a lot is a high bin for everyone.

4 · Case 1b — missing GABA: a geometric source cloud

The simulated cube is far smaller than the connection kernels reach, so most of a neuron's striatal GABA afferents sit outside the lattice. Each of the 7 connected pairs (dSPN→dSPN, dSPN→iSPN, FS→dSPN, FS→FS, FS→iSPN, iSPN→dSPN, iSPN→iSPN) gets a compensation stream. Here the shared fraction cannot be one number — it must fall with distance between two receivers.

Step 1b (build_geometric_source_pools) makes the unsimulated neurons actual points: virtual sources scattered at the real density (divided by multiplicity — one virtual source stands for 10 real neurons) in a box that extends Rout beyond the receivers, connected to every receiver with the model's own kernel. A receiver's pool is whatever sources it connected to.

Per bin, spikes are thrown at the whole cloud and scattered (simulate_receiver_counts_geometric_to_memmap):

n_events(t) ~ Binomial(S·k_mult, p)         # all real neurons the cloud stands for
source of each event ~ Uniform{0 … S−1}     # which virtual source spiked
c_i(t) = # events whose source feeds i      # one bincount over (receiver, bin)

5 · Case 1c — CorticalInputs: shared + private split

The BG populations (thal, gpe_arky, gpe_cp, stn; 100 neurons each) have no geometry and one population per stream, so the pool is the simplest possible: split each receiver's N afferents into a part all receivers share and a part each owns alone (simulate_receiver_counts_homogeneous_to_memmap). 

n_shared  = round(f · N)                    # ONE pool for everybody
n_private = N − n_shared                    # per receiver
S(t)   ~ Binomial(n_shared,  p(t))          # drawn once, added to every receiver
P_i(t) ~ Binomial(n_private, p(t))          # per receiver
c_i(t) = S(t) + P_i(t)                      # exactly Binomial(N, p);  corr = f
toy check (N = 10, f = 0.3, 400 000 bins)targetmeasured
mean count per bin2.52.495

In the shipped model every entry of ci.shared_fraction_dict is 0 — certainly wrong physically, but unmeasured; kept as a visible parameter (input_streams/README.md §4.6). At f = 0 the shared pool is empty and receivers are independent given the drive. N per stream is round(proportion · N_total) with N_total = 1000 (thal) / 500 (others), driven by the same seven per-region rate series as case 1a.

6 · Step 2b — the shared rate modulation

Currently switched off. Every r_sc in the shipped configuration is 0 (mc.correlation_dict, mc.cortical_correlation), so p(t) = p_drive(t) and everything below is skipped — pending the scan of TODO.md §25, because these values set the simulated BOLD amplitude directly. This section exists so the machinery is understood before it is turned on.

The presynaptic neurons themselves can be pairwise correlated at r_sc. That is realised as one multiplicative rate modulation all of them share: mean 1, variance σ², autocorrelation timescale τ_c. Its amplitude is solved from the target correlation and — crucially — the window T_meas the target was measured at (solve_modulation_amplitude): 

a    = exp(−dt/τ_c)                          # AR(1) coefficient
W(m) = Var[sum of m AR(1) samples]           # closed form, ou_sum_variance
σ²   = r_sc · m / ((1 − r_sc) · p̄ · W(m))    # m = T_meas/dt

Measured on this laptop (8 logical cores, 15 GB RAM), one phase per fresh process, real per-stream parameters, one TR of bins (23 100 at dt = 0.1 ms), float64 memmaps as in the real cache. Peak RSS is the process high-water mark (VmHWM; baseline after imports ≈ 44 MB).

Inside case 1a the cost is almost entirely the hypergeometric draw: per 5 592-bin chunk, k ~ Binomial(M, p) takes 0.5 ms, the dSPN hypergeometric 349 ms, the memmap write 64 ms. So ~85 % of cache-build time for the cortical streams is rng.hypergeometric, which also means build time scales with R × n_steps and barely with M.

The disk figures reproduce the known ones exactly because they are pure arithmetic: R × n_steps × 8 bytes per stream in the current float64/per-region layout (TODO.md §3 holds the agreed smaller layout, ~120 GiB per condition). The time extrapolation lands in the right range; the measured aggregates come from a different machine state, and 1b pool-degree and per-region R differences make per-stream costs uneven. The practical readings: cache building is disk-bound, not RAM-bound (no phase peaked above 0.6 GB — a full-length build streams chunk by chunk at the same peak), and a full-length cache belongs on the workstations' /scratch, not this laptop's disk.
